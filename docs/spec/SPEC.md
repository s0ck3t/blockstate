# Blockstate (`blockstate`) — Deterministic Agent Governance Framework

## Why

Enterprise AI platform engineers, backend architects, and Model Risk Management (MRM) officers in regulated industries (banking, insurance, healthcare, and telecommunications) are blocked from deploying customer-facing conversational agents because probabilistic ReAct loops grant Large Language Models (LLMs) autonomy over tool execution and workflow transitions—creating unacceptable corporate liability under EU AI Act Articles 12 and 14, UK FCA SYSC 13.7, HIPAA, GDPR, and SOC 2 Type II (`compliance-references.md`). Rather than replacing high-level enterprise orchestrators (LangGraph, Microsoft Semantic Kernel, AutoGen, AWS Bedrock) and falling into the "Enterprise Island Trap", Blockstate (`blockstate`, CLI: `blockstate`) operates as a **transactional compliance execution enclave** exposed via a first-class `as_tool()` adapter (`from blockstate.adapters.langchain import as_tool`). Inside the enclave, Blockstate inverts the agent control hierarchy: the deterministic Python 3.12+ statechart runtime commands 100% of state transitions, guard evaluations, and memory-isolated tool dispatch tables (`glossary.md`) governed by the **Declarative Control Grammar (DCG)** (`@Stage`, `@Transition`, `@Guard`), demoting the LLM to a constrained worker used strictly for bounded semantic slot extraction and natural language rendering, while providing compile-time mathematical dominator proofs in CI/CD before code reaches production.

## Capabilities

- **CAP-1**
  - **intent:** Developers can declare isolated conversational stages using the Declarative Control Grammar (`@Stage`, `@Transition`, `@Guard`) with a unique identifier, target slot schema, allowed tools, optional turn budget, permitted digressions, and deterministic fallback targets so that workflow boundaries are explicitly defined before execution.
  - **success:** Defining two stages with duplicate identifiers raises `DuplicateStageError` (`BLK-CFG-001`) at startup; omitting a stage identifier raises `ConfigurationError` (`BLK-CFG-002`); dynamic runtime generation of stages not present in source code is rejected (`FR-1`, `AD-4`).
- **CAP-2**
  - **intent:** The runtime can evaluate stage transitions exclusively through deterministic stage guards (`@Guard`, `@Transition`) over validated session data so that language model output text can never autonomously alter workflow routing.
  - **success:** 100% of production state transitions are governed by deterministic Python guards in the Declarative Control Grammar (`@Stage`, `@Transition`, `@Guard`) and PEP 695 `Transition[TargetStage]` annotations with 0% probabilistic routing escapes (`SM-1`); a `False` guard retains the active stage or routes to a declared fallback; adversarial prompt text cannot alter a guard's resolved target; placing `Transition` calls inside Pydantic `@field_validator` methods or using dynamic transition targets is rejected by `blockstate check` (`[Blockstate E014]`, `FR-2`, `AD-4`).
- **CAP-3**
  - **intent:** Operators can enforce per-stage maximum turn budgets and immediate model-refusal circuit breakers so that stalled slot collection or upstream AI safety refusals route deterministically to fallback stages rather than looping indefinitely.
  - **success:** When `max_turns` is an integer (default `5`) and `turn_count > max_turns`, the runtime bypasses LLM generation and invokes `on_max_turns_exceeded`; when `max_turns=None` or `<= 0`, turn counts increment without circuit-breaking; an upstream model safety refusal (default threshold `1`) immediately short-circuits to `on_refusal` (`FR-3`, `AD-6`).
- **CAP-4**
  - **intent:** The system can scope outbound model tool schemas on every turn to only the tools whitelisted by the active stage so that the model has zero visibility into unpermitted capabilities.
  - **success:** Inspecting the raw JSON payload sent to any model provider confirms 0 tools outside the active stage's whitelist are present (`FR-4`, `SM-2`, `AD-3`).
- **CAP-5**
  - **intent:** The runtime can restrict tool execution to an isolated per-stage `Dispatch Table` so that hallucinated or injected calls to unpermitted tools cannot execute.
  - **success:** No global callable tool registry exists at runtime; `ToolGatekeeper` exposes an ephemeral `MappingProxyType` with isolated `RunContext[Deps]`; if a model or renderer emits a tool call absent from the active stage's dispatch table, `ToolGatekeeper` raises `SecurityViolationError` (`BLK-SEC-001`), aborts execution with 0 unpermitted tool invocations (`SM-2`), records the violation in `TurnLedger`, and transitions atomically to `on_security_violation` / locked state (`FR-5`, `AD-3`).
- **CAP-6**
  - **intent:** The system can progressively collect and validate flat or deeply nested slot schemas across multiple conversational turns without failing on not-yet-supplied sibling fields.
  - **success:** `PartialSlotModel` (`max_nesting_depth=8`) updates the active `TaskFrame` when fed a single valid leaf field without failing on missing required fields; `Vaulted[T]` fields detokenise exclusively in-memory during `@field_validator(mode="after")` execution before re-binding the `<VAULT:CATEGORY_NN>` token; invalid values capture sanitised `FieldValidationError` objects (`include_input=False`, `include_context=False`) without corrupting previously validated slots (`FR-6`, `SM-7`, `AD-5`).
- **CAP-7**
  - **intent:** The system can compute remaining uncollected slots ($\Delta$) after each turn, short-circuit to re-elicit invalid fields immediately, lock validated fields, and trigger early stage transitions on disqualifying validation breaches.
  - **success:** After each turn, the runtime evaluates $\Delta = \text{RequiredLeafPaths} \setminus \text{HydratedLeafPaths}$ and never prompts for subsequent fields while prior supplied fields remain invalid; validated leaf paths lock in `TaskFrame.locked_slots` with 0 silent overwrites (`SM-7`); a validation breach with a declared `on_breach` target halts slot collection immediately and transitions to the breach stage; the strict target model instantiates once and only once when $\Delta = \emptyset$ (`FR-7`, `AD-5`).
- **CAP-8**
  - **intent:** The system can suspend an active stage and push an isolated child `TaskFrame` onto a bounded `TaskStack` when an incoming utterance matches a permitted digression, handling multi-turn tangents without $\mathcal{O}(N \times M)$ state-graph edges.
  - **success:** Classifying a permitted digression increments `len(stack)` by `1` up to `max_stack_depth=6` (exceeding depth raises `StackOverflowError` `BLK-SEC-003`), restricts child execution to the digression's scoped read-only tools, and raises `UnauthorisedMutationError` (`BLK-SEC-002`) if the child attempts to mutate parent frame slots without explicit authorisation (`FR-8`, `SM-5`, `SM-7`, `AD-2`).
- **CAP-9**
  - **intent:** The system can pop a completed digression `TaskFrame` from `TaskStack` and resume the suspended parent stage at its exact uncollected slot delta while preserving or explicitly updating parent slots.
  - **success:** Resolving a digression via `Transition.pop_frame()` decrements `len(stack)` by `1` during `commit_turn()` after Pass 2 renders; parent slots after pop are byte-for-byte identical to before push unless the parent stage declares `allow_slot_overrides=True` and the child returns a typed `SlotMutation` (`FR-9`, `SM-7`, `AD-2`).
- **CAP-10**
  - **intent:** Developers and CI pipelines can statically inspect agent source files offline via the Declarative Control Grammar (DCG) to extract the statechart topology and detect undecidable dynamic transitions or structural defects without executing user code or network calls.
  - **success:** `blockstate check` parses source via `ast.parse` over `@Stage`, `@Transition`, and `@Guard` declarations for statecharts of up to 500 nodes in `< 50ms` (`SM-C2` prioritising complete AST depth over compile shortcuts); any dynamic reflection or dynamic transition destination (e.g. `getattr(self, dynamic_state)()`) is rejected at compile time with `[Blockstate E014] Dynamic transition destination detected at <file>:<line>. Transitions must reference static State definitions to enable Lengauer-Tarjan dominator verification.`; syntax or malformed transition declarations report exact `(filename, lineno)` (`BLK-AST-001`); unreachable dead stages are flagged (`BLK-AST-002`); and digression sub-graphs that jump into arbitrary main-flow stages instead of returning (`Transition.pop_frame()`) or escalating are rejected (`FR-10`, `AD-4`).
- **CAP-11**
  - **intent:** Compliance officers and CI pipelines can mathematically verify before deployment that mandatory precursor stages dominate all target action stages across single or multi-branch workflows.
  - **success:** `blockstate verify --dominates "<PrecursorStage> -> <ProtectedTarget(s)>"` computes Lengauer-Tarjan dominators in `< 2s` in CI (`SM-3`); when the precursor dominates every path from root to all specified targets, it exits with code `0` and emits a JSON/Markdown audit certificate; if any branch path bypasses the precursor (or violates DCG static target rules with `[Blockstate E014]`), it exits with code `1` and outputs the exact violating transition path (`FR-11`, `AD-4`, `AD-11`).
- **CAP-12**
  - **intent:** Users can export verified statechart topologies and per-stage tool boundaries as visual diagrams and machine-readable schemas for compliance review and audit documentation.
  - **success:** `blockstate export --format mermaid` emits valid Mermaid flowchart definitions displaying stage nodes, whitelisted tool tags, and guard annotations; `blockstate export --format json` outputs the complete machine-readable topology and stage tool schema (`FR-12`, `AD-4`).
- **CAP-13**
  - **intent:** The runtime can classify user intents and extract candidate slots within a sub-100ms Pass 1 routing budget before deterministic statechart evaluation so that interactive latency SLAs are met.
  - **success:** `IntentClassifier.extract()` enforces a `100ms` default budget; local ONNX/ModernBERT System-1 classifiers achieve p95 extraction latency `<= 50ms`; SLM-classified turns achieve p95 end-to-end turn latency `< 200ms` (`SM-4`); utterances that cannot be mapped to a valid slot, transition, or permitted digression fail safe into clarification or escalation without probabilistic guessing (`FR-13`, `SM-C1`, `AD-6`).
- **CAP-14**
  - **intent:** Stages can dispatch fixed regulatory disclosures or structured multiple-choice menus (`ChoicePayload`) in Pass 2 without invoking a generative model.
  - **success:** Stages configured with `canned_response` or `choice_options` complete full end-to-end turn execution (Pass 1 + core statechart + Pass 2 render) in `< 120ms` (`FR-14`, `SM-4`, `AD-6`).
- **CAP-15**
  - **intent:** The system can sanitise user utterances and tool outputs through a `PIIVault` boundary that replaces sensitive PII/PHI with deterministic session-scoped opaque tokens, encrypts the token map at rest, and restricts detokenisation to authorised tool arguments.
  - **success:** 0 raw PII strings appear in outbound LLM prompts, validation error messages, OpenTelemetry spans, `TurnLedger` records, or `.blockstate/traces.jsonl`; `SessionCheckpoint.vault_map` is encrypted with AES-256-GCM bound to `AAD = "<session_id>:<schema_version>:<revision_id>"`; detokenisation outside `Vaulted[T]` validator checks occurs exclusively in `ToolGatekeeper.invoke()` for parameters annotated as `Detokenise[T]` or via `context.vault.detokenise()`, and tool outputs are re-sanitised before entering state (`FR-15`, `AD-7`).
- **CAP-16**
  - **intent:** The runtime can record every conversational turn as an immutable, cryptographically hash-chained `TurnLedger` entry for tamper-evident regulatory non-repudiation.
  - **success:** `StatechartEngine.commit_turn()` computes each `TurnLedgerRecord` as the SHA-256 digest over the RFC 8785 JCS canonicalisation of `(prev_record_hash, session_id, turn_index, stage_from, stage_to, exposed_tools, prompt_hash, vaulted_input_hash, vaulted_output_hash, guard_outcome, timestamp_utc)`; modifying any byte in a historical record invalidates the cryptographic hash chain of all subsequent records (`FR-16`, `SM-6`, `AD-8`).
- **CAP-17**
  - **intent:** The system can flush `TurnLedger` records asynchronously in strict causal order per session with crash-safe recovery so that audit persistence never degrades turn latency or loses records on worker shutdown.
  - **success:** Slow `LedgerSink` I/O (`PostgresLedgerSink`, `S3LedgerSink`, `FileLedgerSink`) never blocks client turn latency; distributed writes for the same `session_id` preserve monotonic `turn_index` and SHA-256 chain validity; worker `SIGKILL` or `SIGTERM` recovers or drains unacknowledged records via `SessionCheckpoint.pending_ledger_outbox` and `.blockstate/wal/ledger.wal` (10s drain timeout) with 0 lost audit records (`FR-17`, `AD-8`).
- **CAP-18**
  - **intent:** Operators can persist and reload session checkpoints across interchangeable v1 storage backends via the formal async `StorageBackend` SPI (`src/blockstate/ports/storage.py`) with optimistic concurrency control and automatic schema migration.
  - **success:** Switching between the three canonical v1 `StorageBackend` / `StateStore` backends—**In-Memory** (`InMemoryStateStore` for hermetic unit testing and CI/CD), **Local SQLite with WAL mode** (`SQLiteStateStore` using `PRAGMA journal_mode=WAL` via `aiosqlite` at `.blockstate/state.db` for zero-dependency local development and edge deployments), and **PostgreSQL via async SQLAlchemy** (`PostgresStateStore` using `SQLAlchemy[asyncio]` + `asyncpg` for cloud production workloads)—requires zero changes to agent stage code, passes 100% of `StateStoreContractSuite` (including optimistic CAS on `revision_id`), and automatically migrates older checkpoint payloads via pure `SchemaUpcaster` functions on load, while deferring Redis, Microsoft SQL Server, and AWS DynamoDB drivers to v1.2+ via the formal `StorageBackend` SPI (`FR-18`, `AD-9`, `AD-11`).
- **CAP-19**
  - **intent:** The runtime can serialise concurrent requests for the same session via a fail-fast distributed lease with automatic heartbeats and bounded TTL so that parallel utterances cannot cause race conditions or permanent deadlocks.
  - **success:** `StorageBackend.acquire_lease()` / `StateStore.acquire_lease()` enforces a `2000ms` acquisition timeout (raising `ConcurrentSessionError` `BLK-CON-409` on contention), a `30000ms` TTL, and a `10000ms` background heartbeat during active turn/tool execution; crashed worker leases release automatically after `30s` (`FR-19`, `AD-9`).
- **CAP-20**
  - **intent:** External general-purpose LLM orchestrators (such as LangGraph, Microsoft Semantic Kernel, AutoGen, and AWS Bedrock) can invoke a Blockstate workflow as a transactional compliance execution enclave via a first-class `as_tool()` adapter or streaming sub-flow and receive a strictly typed terminal result upon completion.
  - **success:** `from blockstate.adapters.langchain import as_tool` (e.g. `langgraph_agent.bind_tools([as_tool(MortgageOriginationEnclave, name="execute_mortgage_transaction")])`), `Agent.as_tool()`, and `Agent.run_as_subflow()` accept only `(session_id, user_message, initial_context)` and yield/return `BlockstateTurnYield(session_id, state="in_progress", message, choices, missing_slots)`, `BlockstateTurnAborted(session_id, state="aborted", error_code, reason)`, or `BlockstateTurnComplete[T](session_id, state="completed", result: T, ledger_head_hash)` while keeping internal dispatch tables and mutable engine state inaccessible (`FR-20`, `AD-10`).
- **CAP-21**
  - **intent:** Developers and SREs can replay any session turn-by-turn from local trace files or storage backends and emit standardised telemetry spans to isolate production issues rapidly.
  - **success:** `blockstate trace --session <session_id> [--file <path>] [--format table|json]` renders turn timelines, input hashes, slot hydration deltas, stage transitions, `exposed_tools`, and SHA-256 chain status from `.blockstate/traces.jsonl` or configured `StorageBackend`/`TurnLedger` backends alongside OpenTelemetry GenAI 1.30 spans, enabling failure isolation in `< 5` minutes (`FR-21`, `SM-6`, `NFR-10.3`, `AD-14`).
- **CAP-22**
  - **intent:** The runtime can separate persistent cross-flow verified session facts (`Global SessionState`) from ephemeral stage execution state (`TaskFrameState`) so that digressions and frame lifecycle events never corrupt verified session context.
  - **success:** `Global SessionState` persists atomically alongside `TaskStack` in `SessionCheckpoint`; child frames receive read-only access by default, and pushing, popping, or aborting a `TaskFrame` leaves verified facts in `Global SessionState` uncorrupted (`FR-22`, `SM-7`, `AD-2`, `AD-9`).
- **CAP-23**
  - **intent:** Framework and third-party adapter authors can validate storage, ledger, classifier, renderer, and PII-stripper implementations against reusable contract test suites and property-based fuzzers.
  - **success:** All v1 adapters pass 100% of `StateStoreContractSuite`, `LedgerSinkContractSuite`, `PIIStripperContractSuite`, `IntentClassifierContractSuite`, and `ResponseRendererContractSuite`; `Hypothesis` suites (`max_examples=500`) verify `PartialSlotModel` recursive hydration and Lengauer-Tarjan dominator equivalence; CI enforces `>= 95%` line / `>= 90%` branch coverage on `blockstate.core`, `blockstate.compiler`, and `blockstate.security`, and `>= 90%` line / `>= 85%` branch coverage overall (`AD-11`).
- **CAP-24**
  - **intent:** Repository maintainers and enterprise adopters can enforce permissive runtime dependency licensing, block secret or PII commits prior to push, and run canonical domain reference agents out of the box.
  - **success:** Pre-commit and CI gates (`gitleaks`, `detect-secrets`, `blockstate-pii-guard`, `pip-licenses`, `cyclonedx-py`, `pip-audit`, `bandit`) block any copyleft runtime dependency, out-of-sync `THIRD_PARTY_LICENSES.md`/SBOM, `.env` file, credential, or raw PII pattern; all four reference agents in `examples/` (`01_motor_insurance_claim.py`, `02_banking_kyc_dominator.py`, `03_healthcare_hipaa_vault.py`, `04_langchain_subflow_handoff.py`) pass `blockstate verify` and integration tests (`AD-12`, `AD-13`).

## Constraints

- **Inversion of Control & Fail-Closed Routing (`SM-1`, `SM-C1`, `AD-2`, `AD-6`):** The Python statechart runtime owns 100% of state transitions, guard evaluations, and tool dispatch tables; the LLM is never permitted to select transitions or execute unwhitelisted tools, and any utterance that cannot be mapped to a valid slot, transition, or permitted digression must fail closed into clarification or escalation—never guess.
- **Python 3.12+ & Declarative Control Grammar (DCG) AST Constraints (`NFR-10.2`, `SM-C2`, `AD-4`):** Runtime baseline is Python `>=3.12,<3.15` using PEP 695 type syntax and PEP 561 `py.typed` (`mypy --strict` and `pyright` clean). Because Rice's Theorem makes static reachability over arbitrary Turing-complete Python reflection (such as `getattr(self, dynamic_state)()`) mathematically undecidable, all statechart topology must be authored via the **Declarative Control Grammar (DCG)** (`@Stage`, `@Transition`, `@Guard`). `eval()`, `exec()`, dynamic stage generation, dynamic transition destinations (which terminate compilation with `[Blockstate E014]`), and `Transition` references inside `@field_validator` methods are prohibited so `blockstate check` and `blockstate verify` can statically extract 100% of the statechart offline, prioritising proof correctness over compilation speed (`SM-C2`).
- **Hexagonal Core Isolation & Performance Budgets (`NFR-10.1`, `AD-1`, `AD-6`):** `blockstate.core`, `blockstate.compiler`, `blockstate.security`, and `blockstate.ports` (including the formal async `StorageBackend` SPI in `src/blockstate/ports/storage.py`) may import only the Python standard library, `pydantic`, `pydantic-settings`, and `cryptography` (enforced via `import-linter` and gated behind PEP 621 optional extras in `blockstate.adapters.*`, detailed in `ARCHITECTURE-SPINE.md`), maintaining `<= 5ms` core turn overhead (`< 2ms` in-memory state/guard evaluation), `<= 40MB` resident worker RAM without local weights, `max_session_turns=50` per session, and `>= 250` concurrent turns/sec on a 2 vCPU worker.
- **Single-Owner State Mutation & Bounded Stack (`AD-2`):** Exclusively `StatechartEngine.commit_turn()` may commit mutations to `SessionCheckpoint`; stage guards, classifiers, and tool handlers receive frozen `ReadOnlySessionView` projections and return declarative command objects (`SlotDelta`, `SlotMutation`, `VaultDelta`, `Transition`), with `TaskStack` bounded to `max_stack_depth=6`.
- **Zero-Leakage PII, Error & Secret Hygiene (`NFR-10.2`, `AD-7`, `AD-13`, `AD-14`):** Session lease acquisition must precede `PIIVault.sanitise()` at ingress; `vault_map` must be AES-256-GCM encrypted with `AAD = "<session_id>:<schema_version>:<revision_id>"`; Pydantic validation errors must strip raw inputs (`include_input=False`, `include_context=False`); exception tracebacks must set `capture_locals=False`; all environment secrets must load via `BlockstateSettings` (`BLOCKSTATE_` prefix) typed as `pydantic.SecretStr`.
- **Permissive Apache-2.0 Licensing & Supply-Chain Allowlist (`AD-12`):** Blockstate is open-source under Apache-2.0 with zero cloud telemetry; all core and optional runtime dependencies must use `MIT`, `Apache-2.0`, `BSD-2-Clause`, `BSD-3-Clause`, `PSF-2.0`, or `ISC` licences (`hypothesis` MPL-2.0 restricted strictly to dev/test; `litellm` pinned `<1.107.0`).
- **Glossary, British English & Developer Ergonomics (`SM-5`, `AD-14`):** All code, CLI outputs, deterministic error codes (`BLK-<DOMAIN>-<NNN>` and `[Blockstate E014]`), OpenTelemetry GenAI 1.30 spans, 12-factor `stdout` JSON logs, and documentation must use the verbatim terms in `glossary.md` and British English spelling (`sanitise`, `tokenise`, `serialise`, `authorise`, `behaviour`, `colour`), enabling a multi-slot stage with digression handling to be authored in `< 50` lines of standard Python (`SM-5`).

## Non-goals

- **Replacing High-Level Outer Orchestrators ("Enterprise Island Trap"):** Blockstate does not replace outer enterprise orchestrators (LangGraph, Microsoft Semantic Kernel, AutoGen, AWS Bedrock); it operates as a transactional compliance execution enclave mounted via `from blockstate.adapters.langchain import as_tool`.
- **Autonomous Goal Seeking or Unbounded ReAct Loops:** No open-ended autonomous agents, web-crawlers, or distributed multi-agent inter-process buses in v1.
- **Proprietary External DSL Files:** No custom non-Python domain-specific language files (such as Colang); all stage configurations, schemas, and guards use standard type-annotated Python constrained by the Declarative Control Grammar (`@Stage`, `@Transition`, `@Guard`).
- **Global Mandatory Confirmation Steps:** No globally forced user confirmation prompts before every action; confirmations are configured per stage only where business logic requires them.
- **Transitions Inside Pydantic Validators or Dynamic Reflection:** Declaring stage transition targets inside `@field_validator` methods or routing via dynamic Python reflection (`getattr(self, dynamic_state)()`) is unsupported and rejected at compile time (`[Blockstate E014]`).
- **Code-First Visual Statechart Studio & Python AST Generator (`blockstate studio` / `blockstate graph --live`) Deferred to v1.1/v1.2:** v1 core excludes a runtime JSON-canvas workflow interpreter (like Langflow/Flowise) because runtime JSON blobs bypass static Python AST compilation (`[Blockstate E014]`). Instead, v1.1/v1.2 introduces `blockstate studio`—a code-first visual statechart canvas and live Lengauer-Tarjan dominator inspector that reads `.py` files via `ast.parse`, generates clean Python DCG `.py` files (Tier 1), and performs surgical bidirectional AST/CST decorator patching via `libcst` (Tier 2).
- **Bespoke LLM HTTP Client Wrappers:** Delegated strictly to `PydanticAI` and `LiteLLM` adapters.
- **Retroactive Time-Travel Rewind DAGs:** No automated rollback of external API side effects; backtracking requires explicit forward-compensating stages or re-entry routes.
- **Heavyweight Formal SMT/Policy Solvers:** Rejects Z3/TLA+ in favour of `< 50ms` Lengauer-Tarjan graph dominator verification over the Declarative Control Grammar.
- **v1.1/v1.2+ Extended Enclave Wrappers, Storage Drivers & v2 Enterprise Buses, Multi-Language SDKs & Conversation Fuzzer:** First-class `as_tool()` wrappers for Microsoft Semantic Kernel, AutoGen, and AWS Bedrock Agents (`v1.1`), plus Redis, Microsoft SQL Server, and AWS DynamoDB storage backends (`v1.2`) are scheduled via the formal async `StorageBackend` SPI (`src/blockstate/ports/storage.py`); managed message buses (Kafka, AWS SQS, GCP Pub/Sub), Oracle Database, Azure Cosmos DB, Go/TypeScript/Rust SDKs, and automated adversarial conversation fuzzing CLI (`blockstate fuzz`) are scheduled for v2.0+ (see [`docs/ROADMAP.md`](../ROADMAP.md)).
- **CLI Project Template Generator (`blockstate init --template`) & Built-In Dialogue Repair Prompt Templates (`v1.1`/`v1.2`):** Scheduled for `v1.1` (`blockstate init`) and `v1.2` (`blockstate.core.repair`); in v1.0 core, quick-start scaffolding is provided by the canonical domain reference scripts in `examples/` and `README.md`, and Pass 2 `ResponseRenderer` receives sanitised `FieldValidationError` objects directly.

## Success signal

- A platform engineer authors a multi-slot regulated workflow enclave (such as motor insurance claims, mortgage origination, or tiered loan disbursement) with digression handling in `< 50` lines of typed Python using the Declarative Control Grammar (`@Stage`, `@Transition`, `@Guard`, `SM-5`), mounts it into LangGraph via `as_tool(MortgageOriginationEnclave, name="execute_mortgage_transaction")`, proves in CI via `blockstate verify` in `< 2s` that identity verification mathematically dominates every payout branch while rejecting dynamic transitions with `[Blockstate E014]` (`SM-3`), and executes multi-turn sessions sustaining `< 200ms` p95 SLM turn latency (`< 120ms` for templates/`ChoicePayload`, `SM-4`) with 100% deterministic guard transitions (`SM-1`), 0 unpermitted tool exposures (`SM-2`), 0 silent slot overwrites (`SM-7`), and a tamper-evident SHA-256 `TurnLedger` replayable in `< 5` minutes via `blockstate trace` (`SM-6`).

## Assumptions

- Enterprise engineering and MRM teams in regulated industries prioritise compile-time mathematical dominance proofs, deterministic enclave execution, and seamless `as_tool()` integration into existing outer orchestrators over open-ended conversational autonomy (`PRD §2.1`).
- Python `>=3.12,<3.15` (leveraging PEP 695 type parameter syntax and PEP 701) is the mandatory baseline runtime, superseding the earlier Python 3.11+ mention in the PRFAQ, and the `<= 5ms` core turn overhead budget encompasses the `< 2ms` pure in-memory state/guard evaluation target (`PRD §4.1`, `NFR-10.1`, `AD-1`, `AD-6`).
- HMAC-SHA256 session-scoped opaque tokenisation (`<VAULT:CATEGORY_NN>`) paired with AES-256-GCM encryption (`cryptography` package, `BLOCKSTATE_VAULT_SECRET_KEY`, and AAD binding) satisfies enterprise PII/PHI boundary isolation (`PRD §4.7`, `AD-7`, `ASSUMPTION-A2`).
- Packaging and lockfile governance standardise on `uv` (`>=0.13.6`) and `hatchling` (`>=1.27.0`) with PEP 621 optional extras; v1 slices storage strictly to three canonical backends behind the async `StorageBackend` SPI (`src/blockstate/ports/storage.py`)—`In-Memory`, `Local SQLite with WAL mode` (`PRAGMA journal_mode=WAL` via `aiosqlite`), and `PostgreSQL via async SQLAlchemy` (`SQLAlchemy[asyncio]` + `asyncpg`)—all verified by `StateStoreContractSuite` on every PR, while deferring Redis, Microsoft SQL Server, and AWS DynamoDB to v1.2+; upstream model safety refusals default to a circuit-breaker threshold of `1` refusal (`PRD §8.4`, `PRD §8.5`, `AD-9`, `AD-11`, `ASSUMPTION-A1`).
