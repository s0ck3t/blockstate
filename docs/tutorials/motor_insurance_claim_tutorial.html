1. The Problem: Probabilistic Autonomy in Regulated Domains

Most conversational AI frameworks let a large language model determine execution control: the model decides which tools to invoke, which branches to take, and when a task is completed.

In regulated environments such as insurance claims handling, retail banking, and clinical triage, probabilistic control creates unacceptable legal exposure. An insurance claim agent must never bypass identity verification, calculate settlement payouts using hallucinated logic, or authorise repairs for impaired drivers. Under regulatory frameworks like the UK Financial Conduct Authority (FCA) Consumer Duty and the European Union AI Act, organisations require mathematical certainty that compliance checkpoints cannot be avoided.

The Blockstate Approach: Blockstate enforces strict separation between workflow control and natural language generation. The state machine is written in pure Python using Declarative Control Grammar (DCG). The language model serves as a semantic slot extractor (Pass 1) and empathetic dialogue generator (Pass 2). It possesses zero authority to mutate state or skip compliance gates.

2. Architecture: Declarative Statechart & Two-Pass Execution

The motor claims workflow guides a policyholder through authentication, answers policy digressions without losing state, captures accident details, evaluates underwriting liability, and routes to either an approved bodyshop or a senior claims adjuster:

  • Policy Verification: Collects policy number and UK postcode, querying policy records with detokenised parameters.
  • Pushdown TaskStack Digressions: Handles inquiries (No Claims Discount, Excess, Courtesy Car) via call-return stack semantics. When the FAQ finishes, the frame pops and resumes data collection.
  • Underwriting & Liability Assessor: Inspects incident narratives for statutory driver impairment (falling asleep, mobile phone usage, intoxication), zero-damage claims, and third-party liability disputes.
  • Compile-Time Dominator Proofs: The Lengauer-Tarjan dominator tree algorithm verifies that verify_policy dominates all settlement stages before the system can boot.

class IncidentIntakeSlots(BaseModel):
    """Slot schema for First Notice of Loss incident narrative and parameters."""
    incident_date: str = Field(..., description="Date of accident in YYYY-MM-DD format")
    incident_description: str = Field(..., description="Circumstances and physical damage description")
    is_drivable: bool = Field(True, description="Whether the insured vehicle remains roadworthy")
    third_party_involved: bool = Field(False, description="Whether third-party vehicles or property were involved")
    driver_impairment: str = Field("none", description="Declared driver condition: none, fatigued_or_asleep, alcohol, mobile_phone")
    damage_severity: str = Field("minor_cosmetic", description="Physical impact severity: none, minor_cosmetic, moderate, severe_structural")

    @field_validator("incident_date")
    @classmethod
    def validate_incident_date(cls, v: str) -> str:
        target_date = datetime.date.fromisoformat(v.strip())
        today = datetime.date.today()
        if target_date > today or (today - target_date).days > 30:
            raise ValueError("Incident date invalid or outside 30-day reporting limit")
        return target_date.isoformat()

3.2 Policy Administration System (PAS) & Statechart Guard Enforcement

The statechart pairs stage handlers with deterministic guards that verify genuine active policy records from the PAS database: 

class MotorInsuranceClaimAgent(Agent):
    @Stage(name="verify_policy", collect=PolicyVerificationSlots, tools=[lookup_policy_record], allow_digressions=["ncb_faq", "excess_faq", "courtesy_car_faq"])
    @Transition(targets=["incident_details"])
    def verify_policy_stage(self, slots: PolicyVerificationSlots) -> Transition[str | None]:
        policy = SHARED_TOOL_CONTEXT.get("policy_record")
        if slots.policy_number and slots.postcode and policy and policy.get("status") == "active":
            return Transition.to("incident_details")
        return Transition.stay()

    @Guard(stage="verify_policy", targets=["incident_details"])
    def guard_policy_verified(self, slots: PolicyVerificationSlots | None) -> Transition[str | None]:
        policy = SHARED_TOOL_CONTEXT.get("policy_record")
        if slots and policy and policy.get("status") == "active" and slots.policy_number.upper() == policy.get("policy_number", "").upper():
            return Transition.to("incident_details")
        return Transition.stay()

    @Stage(name="fast_track_settlement", terminal=True, tools=[authorise_repair_network])
    def fast_track_stage(self) -> Transition[dict[str, Any]]:
        tool_res = authorise_repair_network()
        policy = SHARED_TOOL_CONTEXT.get("policy_record") or {}
        # Derives claim reference, excess, and courtesy car allocation from verified policy
        return Transition.end(result={
            "claim_status": "approved_fast_track",
            "claim_reference": f"CLM-GB-{abs(hash(policy.get('policy_number', '782910'))) % 90000 + 10000}",
            "excess_applied_gbp": policy.get("total_excess_gbp", 350.00),
            "courtesy_car_allocated": policy.get("courtesy_car_entitlement", True),
            "booking_reference": tool_res.get("booking_reference"),
            "repairer_name": tool_res.get("repairer_name"),
        })
